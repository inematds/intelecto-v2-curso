Aula 8 · 14 min

Seu Jarvis do seu jeito

O assistente já conversa, lembra e tem freios. A operação contínua é opcional: no Linux, um serviço pode ligar o bot ao iniciar a sessão. Termine com uma revisão das proteções e escolha só o próximo passo que você vai usar.

Começar a aula

Nesta aula você vai

  1. 1Revisar o que está ativo
  2. 2Entender o serviço Linux opcional
  3. 3Separar o que foi testado do que ainda falta testar

Objetivo: Conferir memória, auditoria e proteção; se usar Telegram no Linux, preparar o serviço do usuário.

01 · Sua operação segura

O caminho termina com uma conferência, não com um botão mágico.

Clique em cada bloco do diagrama para ver o que ele faz.

Clique em cada parte para ver sua função.

02 · Antes de deixar ligado

Clique em cada etapa para ver o que fazer.

1. Confira estado

O comando confere instalação, banco, configuração e segredos exigidos pelas opções ativas.

2. Leia registros

“Feito” na resposta não é o recibo. auditoria -n 20 imprime linhas JSON: comando é o pedido, classe é livre/aprovar/bloqueado, rodou diz se executou, decisao explica o motivo.

3. Ative só o necessário

O serviço de exemplo usa systemd, gerenciador de serviços do Linux, para ligar o Telegram. journalctl mostra os registros desse serviço. Se você usa só o terminal, não precisa instalá-lo.

4. Reconheça limites

Ollama local, Linux e a caixa por comando com Docker foram testados ao vivo. OpenRouter, Telegram ao vivo e macOS não foram testados ao vivo pelo INEMA. Windows só pelo WSL com Ubuntu, também sem teste ao vivo.

03 · Sua revisão final

WorkingDirectory e ExecStart são a pasta e o comando que o serviço roda. Confira esses caminhos no arquivo antes de copiar; o exemplo presume o clone em ~/intelecto-v2.

Terminal · estado, memória e histórico
cd ~/intelecto-v2
python3 -m intelecto verificar
python3 -m intelecto memoria
python3 -m intelecto auditoria -n 20
Linux · serviço Telegram opcional
cd ~/intelecto-v2
cat servico/intelecto-telegram.service
# Confira WorkingDirectory e ExecStart; ajuste se necessário.
mkdir -p ~/.config/systemd/user
cp servico/intelecto-telegram.service ~/.config/systemd/user/
systemctl --user daemon-reload && systemctl --user enable --now intelecto-telegram
Linux · acompanhar o serviço
cd ~/intelecto-v2
journalctl --user -u intelecto-telegram -f
Exemplo do repositório
{"ts": "2026-11-13T03:38:00+00:00", "tipo": "comando", "comando": "ls", "classe": "livre", "rodou": true, "decisao": "livre (só leitura)"}

Nesta linha, comando é ls, classe é livre, rodou é true e decisao explica por que passou.
