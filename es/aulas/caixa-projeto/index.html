Clase 7 · 20 min

La caja del agente en tu proyecto

Necesitas Docker instalado en la clase 6; solo las clases 6 y 7 requieren Docker. Aquí, la caja del agente trabaja en una copia del proyecto. Haz un cambio pequeño sin claves, lee el patch y decide si lo aplicas. También aprenderás cómo dejar que los agentes trabajen en una copia, con un ejemplo opcional que no se ejecuta en este curso.

Empezar la clase

En esta clase vas a

  1. 1Entender cómo crear, ejecutar y destruir
  2. 2Revisar el patch y aplicarlo conscientemente
  3. 3Leer la nota del auditor sin confundirla con la nota del modelo

Objetivo: Crear y leer un patch sin claves, aplicar el cambio revisado al proyecto y deshacerlo.

02 · Dos herramientas del kit

Haz clic en cada etapa para ver qué hacer.

1. caixa.sh

El flujo crear → ejecutar → destruir usa una copia: .env, las claves .pem y ~/.ssh quedan fuera. La imagen Docker es el molde de la caja; sin --aplicar, el original queda intacto. Hay límites de memoria, CPU y tiempo.

Con --rede, la caja obtiene acceso a la red. Con --env ANTHROPIC_API_KEY, solo entra esa clave. El comando opcional con agente usa tu clave y puede enviar el contenido de la copia al servicio del agente; no se ejecutó en este curso. --dangerously-skip-permissions desactiva las preguntas internas del agente en la copia. Revisa el parche antes de aplicarlo.

En macOS, caixa.sh también necesita el comando timeout: instala coreutils con brew install coreutils, como indica el README del kit.

2. Parche

Un parche es un archivo de texto con los cambios. El .patch queda en la carpeta desde la que ejecutaste caixa.sh o en la carpeta indicada por --patch PASTA. Léelo con less (presiona q para salir) antes de aplicarlo. En patch -p1, -p1 quita la primera parte de la ruta, “antes/” o “trabalho/”, para que coincida con el archivo de tu carpeta. Usa el nombre exacto que muestra la caja.

Para un archivo nuevo, la línea antes/ en el encabezado del parche puede mostrar 1969; representa que el archivo no existía antes de la ejecución.

3. auditar.py

El auditor lee Claude Code, Codex y DeepSeek Harness instalados en la computadora, además del proyecto. Harness es el programa que ejecuta los comandos del modelo; el sandbox limita a qué puede acceder. Si no tienes ninguno de esos programas, la nota será baja y es normal; no mide la inteligencia de la IA.

4. Caso real

La primera práctica usa ~/intelecto-v2 y la imagen pública python:3.12-slim; no pide una clave ni un agente en la nube. La segunda ejecuta pruebas en una imagen preparada con pytest, el programa de pruebas de Python. El README del proyecto documenta 67 pruebas aprobadas y 1 omitida en una medición anterior; revisa tu propio resultado.

03 · Crea, lee y aplica un parche sin clave

Docker de la lección 6 ya debería funcionar. Empieza en tu carpeta personal y usa la ruta completa de caixa.sh; el parche queda en ~. Sustituye AAAAMMDD-HHMMSS por el nombre que muestre la caja.

Terminal · descarga el kit una vez
cd ~ && git clone https://github.com/inematds/caixa-do-agente
macOS · requisito de caixa.sh
brew install coreutils
Ubuntu · comprobar las herramientas de la caja y del parche
rsync --version
patch --version
# si falta alguna:
sudo apt install -y rsync patch
Terminal · crear una nota en la copia, sin clave
cd ~ && ~/caixa-do-agente/caixa.sh ~/intelecto-v2 --imagem python:3.12-slim -- sh -c "echo teste > nota.txt"
Terminal · leer el parche (q sale de less)
less ~/caixa-AAAAMMDD-HHMMSS.patch
Terminal · aplicar el parche leído
cd ~/intelecto-v2 && patch -p1 < ~/caixa-AAAAMMDD-HHMMSS.patch
cat nota.txt
Terminal · deshacer la nota de prueba
cd ~/intelecto-v2 && rm nota.txt
Segunda práctica · pruebas en la imagen del proyecto
cd ~/intelecto-v2
docker build -t intelecto-v2-testes caixa/
cd ~/caixa-do-agente
./caixa.sh ~/intelecto-v2 --imagem intelecto-v2-testes -- python3 -m pytest -q -p no:cacheprovider
Opcional · auditar el proyecto
cd ~/caixa-do-agente
python3 auditar.py ~/intelecto-v2
OPCIONAL · ejemplo de agente en la caja, no ejecutado en este curso
cd ~/caixa-do-agente
./caixa.sh ~/meu-projeto --rede --env ANTHROPIC_API_KEY -- npx -y @anthropic-ai/claude-code -p "rode os testes" --dangerously-skip-permissions

Estas cifras están documentadas en las fuentes; no se capturaron en esta ronda. La cantidad puede cambiar en tu proyecto.

04 · Qué hace el ejemplo opcional con agente

Este ejemplo del README de caixa-do-agente no se ejecutó en este curso. Usa tu clave ANTHROPIC_API_KEY y envía la copia del proyecto por la red al servicio del agente. Esto puede consumir tu suscripción o créditos del servicio.

./caixa.sh ~/meu-projeto copia ese proyecto; --rede permite el acceso a internet; --env ANTHROPIC_API_KEY pone solo esa clave en la caja. Después de --, npx -y @anthropic-ai/claude-code -p "rode os testes" inicia el agente con ese pedido; --dangerously-skip-permissions elimina las preguntas internas en la copia. La caja genera un parche para que lo revises antes de aplicarlo al original.

05 · Haz la prueba de la maqueta

Sigue el orden y marca cada punto solo después de comprobar el resultado.

Haz el cambio y vuelve al original

12

En la carpeta personal, ejecuta el comando sin clave de la imagen python:3.12-slim usando ~/caixa-do-agente/caixa.sh. Copia el nombre del parche impreso. Abre ese archivo con less, presiona q para salir; entra en ~/intelecto-v2, aplícalo con patch -p1, comprueba con cat nota.txt y deshazlo con rm nota.txt.

Listo cuando: El parche leído contiene +teste; patch imprime “patching file nota.txt”; cat muestra “teste”; después de rm, la nota de prueba no queda en el original.

Ejecuta las pruebas en otra caja

8

En ~/intelecto-v2, crea la imagen intelecto-v2-testes con docker build. Después, en ~/caixa-do-agente, ejecuta caixa.sh con esa imagen y python3 -m pytest -q -p no:cacheprovider. La batería bash testes/teste.sh del kit es opcional.

Listo cuando: pytest muestra el resumen de tus pruebas y la caja informa cuántos archivos cambiaron; compara con la medición documentada, sin exigir las mismas cifras.

07 · Lo que te llevas de esta clase

Crea, ejecuta, destruyeLa caja trabaja en una copia sin .env ni claves y empieza sin red. Con --rede, el contenido de la copia puede enviarse; los recursos siguen siendo limitados.
Tú decidesEl parche muestra los cambios. patch -p1 aplica el archivo leído; --aplicar inicia otra ronda y pregunta antes de copiar.
Nota con contextoLa nota depende de los programas de agente instalados en la computadora, no de la inteligencia del modelo.
